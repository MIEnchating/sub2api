# 账号请求指标规则

管理员在账号列表中打开性能规则弹窗，配置请求指标规则和观测阈值。即使账号暂时没有请求记录，也可以进入配置。

## 请求指标规则

列表统计最近 1 小时全部日志，不受下方 10 条请求展示限制。所有实例读取同一数据库，并与规则评估复用同一聚合查询。

- 成功率：已记录成功请求 /（成功 + 失败）。按账号、API Key 和请求 ID 去重；终态失败覆盖同请求的部分输出。免费但有 Token 的成功请求计入，空的失败占位 usage 不计入成功。WS 连接错误单独计失败，不抹去已完成的 WS 轮次。
- 缓存率：成功流式 / WS 请求的缓存读取 Token / 文本提示 Token；排除图片输入，按 Token 加权。
- 平均首字：成功流式 / WS 请求的有效首字时间。
- 平均耗时：成功请求的有效总耗时。

排除赛博计费记录和错误日志中的 count_tokens；没有账号归属的错误不分摊给账号。统计依赖持久化日志，未写入日志的结果未知。缺失或负数耗时、缺失缓存数据不参与该指标；无样本为 `null`，真实零值有效。运维监控关闭时停止规则评估，配置弹窗显示指标未知，不能启用新规则；仍允许关闭或手动解除已有规则。

规则默认关闭。每项指标可填写「低于时暂停」「高于时暂停」，留空不参与；百分数使用 0–100，耗时使用毫秒。每 30 秒评估一次，任一指标样本达到设置值（默认 20）且严格越界即暂停，等于阈值不触发。

## 自动恢复

默认勾选自动恢复，但仅在启用规则后生效：

1. 暂停后冷却（默认 5 分钟，可配置 1–1440 分钟）。
2. 冷却到期开始试运行，每 5 秒最多准入一个正常业务请求，每轮最多放行恢复样本数的 3 倍。
3. 只检查本轮开始后的新样本。全部启用的请求指标规则都达到恢复样本数（默认 3，可配置 1–100），且都在恢复上下限内，才解除暂停。
4. 任一指标达到恢复样本数后越过暂停阈值，或试运行 10 分钟仍未达标，重新暂停并进入下一轮冷却。

恢复阈值留空时沿用对应暂停阈值，也可以设置更严格的恢复条件，避免反复启停。没有流量、指标样本不足、旧样本过期都不算恢复。选择缓存率或首字条件时，必须有足够流式 / WS 请求产生对应指标。

试运行和恢复后的规则评估从本轮开始计数，最多回看 1 小时；弹窗显示实际参与评估的样本。列表仍显示完整最近 1 小时，旧失败因此可能仍显示在列表，但不会立即把刚恢复账号再次暂停。

准入限额存储在数据库，跨实例原子领取。无限并发、代理池和粘性候选也受最终准入门控制；后续并发检查拒绝时返还本次额度，使用配置版本和暂停代次隔离旧回调。

## 状态归属与升级

只修改独立规则表，不改管理员手动调度开关、账号状态、限流或其他暂停原因。在途请求继续执行。保存配置会解除请求指标规则触发的暂停并重新评估。观测阈值触发的暂停须显式解除，手动解除同时关闭评估。自动恢复只解除本规则自身的暂停，管理员禁用的账号不会被自动启用。

新增迁移 `341_account_metric_rules.sql` 保留旧事件，记录 `retire`，禁用旧 HTTP 规则并清除其独立暂停。`342_retire_group_zero_cache.sql` 清理旧分组零缓存配置；旧 Redis 暂停不再被读取，其键按原 TTL 自然过期。没有修改已应用的迁移。升级后需在弹窗中重新配置阈值。归档的旧配置可从审计事件中查阅。

保留管理员 API 的 `/accounts/performance` 批量读取、`/:id/performance` 保存、`/:id/performance/release` 解除及 `/:id/performance/events` 审计路径。配置使用 `version: 2`；保存校验 revision，解除还校验 pause_generation。配置、暂停、试运行、恢复和解除均在事务内写入事件，多实例评估使用行锁。

```json
{
  "version": 2,
  "enabled": true,
  "success_rate": {"pause": {"min": 90, "max": null}, "recovery": {"min": 98, "max": null}},
  "cache_rate": {"pause": {"min": 20, "max": null}, "recovery": {"min": 30, "max": null}},
  "ttft": {"pause": {"min": null, "max": 3000}, "recovery": {"min": null, "max": 2000}},
  "duration": {"pause": {"min": null, "max": null}, "recovery": {"min": null, "max": null}},
  "tps": {"min": null, "max": null},
  "degradation": {"min": null, "max": null},
  "observed_ttft": {"min": null, "max": null},
  "upstream_error": {"min": null, "max": 25},
  "min_samples": 20,
  "auto_recover": true,
  "cooldown_minutes": 5,
  "recovery_samples": 3
}
```

## 观测阈值

观测阈值按全局配置的滚动周期计算有效样本的 TPS、流式首 Token 耗时、完整质量检测轮次的降级比例及本进程上游 HTTP 错误率，默认使用最近 **60 分钟**。每项指标可分别设置低于和高于时暂停的阈值；百分比范围为 0–100。监控默认关闭，未设置的上下限不参与判断。

在「系统设置 → 网关服务 → 账号性能监控周期」填写统计周期，单位为分钟，范围为 1–1440 的整数，默认 **60 分钟**。所有账号的平均 TPS、首字平均值与探针轮次降智率共用这一滚动窗口，仍按实际请求／探针开始时间统计。

保存后，后续统计读取和阈值评估使用新周期，无需重启；账号列表、监控弹窗和说明显示本次统计实际使用的周期。评估频率仍为每 30 秒一次，更改周期不会解除已有监控暂停。

管理员 API 为 `GET /api/v1/admin/settings/account-performance` 和 `PUT /api/v1/admin/settings/account-performance`，请求和响应中的设置结构为：

```json
{"window_minutes": 60}
```

配置使用现有 `settings` 表的 `account_performance_window_minutes` 键持久化，无需新增表或迁移。升级后未配置的安装使用 60 分钟；设置读取失败或存储值不合法时，扩展统计标为不可用，启用了观测阈值的评估返回错误。已持久化的暂停仍然有效。

触发阈值后，监控使用独立暂停标记停止账号的新调度，不覆盖账号原有的启停、冷却或分组状态，也不终止已经在途的请求。人工解除暂停会同时关闭监控，重新开启前需要明确保存配置。编辑阈值、关闭评估和样本过期都会保留观测阈值触发的暂停。

评估任务每 30 秒调度一次，每轮预算 25 秒；超时或失败后从上轮最后尝试的下一个账号继续，避免列表尾部长期无法评估。账号数量和查询耗时仍会影响一轮完整覆盖所需的时间。

区域发布端在同一数据库快照中读取账号和暂停状态，移除暂停账号后再发布完整快照。暂停查询失败时不发布、不延长旧快照的有效期。区域订阅端在调度、账号详情和并发准入时只使用已认证且未过期的本地快照；缺失账号或快照过期均拒绝准入。控制面也拒绝为已暂停账号发放新区域并发授权或续租。

区域传播受配置的同步间隔、快照有效期及现有授权有效期约束，不能保证控制面提交暂停后所有节点立即同步撤销；不会强行回收已占用的槽位。需要即时停用所有节点时，应使用现有的区域撤销/排空流程。

配置、评估和解除暂停都先锁定未删除账号，再变更监控状态与审计记录，避免软删除并发产生新监控操作。批量指标接口不返回软删除账号。

## 平均缓存

账号列表的「性能 · 近60分钟」列及使用同一组件的阈值弹窗新增「平均缓存」。它跟随全局滚动周期，显示有效请求缓存命中率的算术平均：每条请求先计算 `100 × cache_read_tokens / (input_tokens + cache_read_tokens + cache_creation_tokens)`，再按请求等权平均。`input_tokens` 是已归一化的未缓存输入；这不是按 Token 加权的总命中率。

统计复用性能查询中按请求开始时间筛选的完整成功文本请求；缺少唯一完整耗时记录、失败或不完整请求、媒体请求均不计入。三个输入桶必须非负且总和大于零；没有有效样本显示「未采集」，有效零命中显示 `0.0%`。提示说明包含当前周期和样本数。批量性能响应新增 `avg_cache_percent`（百分比或 `null`）与 `cache_samples`，旧服务缺少字段时前端显示「未采集」。

观测平均缓存可以展示，也可在优先调度中按配置的缓存权重参与评分。该值没有独立暂停阈值；请求指标规则中的缓存阈值使用前述按 Token 加权的缓存率。新功能提示使用 `account-average-cache-initial-announcement`，账号列表、阈值弹窗与复用性能组件的优先级分析页共用 ID。

## 上游 HTTP 错误率阈值

账号性能弹窗中的「上游 HTTP 错误率」上下限使用与错误率展示相同的采集器和滚动窗口。错误率为本进程已观测到的上游 HTTP 4xx/5xx 响应数，除以上游 HTTP 2xx–5xx 响应总数，再乘以 100；按收到响应头的时间计算，包含窗口边界。每次重试分别计数，例如同一业务请求先收到 503、再收到 200，错误率样本是 1/2，而非一次最终成功。

采集覆盖通过共用 HTTP 传输的推理 POST，包含使用该传输的探针。收到响应头前的网络失败、取消、本地认证/余额/调度拒绝没有样本；HTTP 200 中的业务错误、不完整流、原生 WebSocket 及绕过该传输的插件路径不在错误统计内。这是上游 HTTP 响应状态错误率，不是全部请求或用户最终失败率。账号名称含 WS 不代表其原生 WS 轮次已经被采集。

观测阈值与请求指标规则共用 `version: 2` 配置，各自读取对应的上下限。上例中的 `ttft` 是可自动恢复的请求指标规则，`observed_ttft` 是完整性能样本上的独立阈值。

在该例中，观测错误率 28.2% 严格高于 25% 时，下次有效评估会添加 `upstream_error` 暂停原因；等于 25% 不触发。没有样本时不触发，也不把缺失值当 0；有成功响应、失败数为零时的 0% 是有效值，可以触发配置的正数下限。没有新增最小样本数限制，单个响应也可参与判断。

证据仅保留在当前服务进程内，最多保存最近 65,536 条响应及 24 小时。进程重启、容量淘汰或保留时限可能使窗口历史不完整；只要存在有效响应样本，仍按已观测部分评估，不等待完整窗口。弹窗说明和暂停审计保留失败数、总数、百分比、来源、保留起点与 `window_complete`。缺样本、样本过期、后续恢复或重启不会解除已持久化的暂停。

多实例不汇总此指标：只有运行现有后台监控任务的 full 节点参与评估，gateway 节点的本地采样不会自动汇入 full 节点。哪个评估进程取得账号监控行锁，就用哪个进程自己的样本判断；该进程可能与管理员读取页面的实例不同。暂停结果按现有数据库、调度和区域传播规则生效，影响该账号的新调度，而不是仅暂停采集实例。跨实例显示不同样本是这一采集口径的限制，不能当作集群总错误率。对于只在其他进程或原生 WS 上有流量的账号，评估进程可能一直没有可用证据。

已发布的第 2 版 JSON 配置缺少 `upstream_error` 时，两侧默认不限制，无需数据库迁移，也不会自动启用监控。回滚旧二进制后该新阈值不再评估；已有独立暂停及显式解除规则仍保留。旧版本整体保存配置可能丢弃未知字段，因此混用版本期间应避免编辑新阈值，升级完成后重新核对配置。新增阈值提示独立于原错误率展示提示，使用稳定 ID `account-upstream-http-error-threshold-initial-announcement`；普通升级不复活已关闭的提示。
